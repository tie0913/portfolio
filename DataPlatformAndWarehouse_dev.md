# Data Platform – Data Processing System

## Overview

Rebuilt and stabilized a failing data platform to improve reliability, latency, and overall system performance.

The platform previously experienced frequent production failures and unreliable data delivery, impacting downstream systems.

---

## My Role

Worked as a data engineer, responsible for data pipeline implementation, system stabilization, and production issue troubleshooting.

Initially focused on building data ingestion systems, then expanded to developing data processing pipelines and backend services (using Spark and Spring Boot) to support internal dashboards.

The implemented solutions were later adopted more broadly across the team to support additional data use cases.

---

## Key Implementation

* Developed CDC ingestion services using Kafka for MySQL and MongoDB to enable real-time data capture
* Built real-time and batch data pipelines using Spark to support analytics and reporting
* Debugged recurring cluster failures and resolved data processing instability issues
* Optimized ETL workflows, reducing CPU and memory usage by over 70%
* Implemented monitoring and alerting mechanisms to improve system observability
* Improved failure handling and recovery logic to ensure reliable data processing

---

## Engineering Challenges

* Frequent production failures with limited monitoring and observability
* High data latency (T+1 processing), affecting real-time data availability
* Unstable data pipelines with resource bottlenecks and inconsistent performance

---

## Results

* Improved system reliability to 99.99% in production
* Reduced data latency from T+1 to near real-time (seconds to minutes)
* Reduced resource usage by over 70% through pipeline optimization
* Achieved stable long-term production operation with significantly fewer incidents

---

## Tech Stack

Kafka, Spark, Hive, Hadoop, MySQL, MongoDB
